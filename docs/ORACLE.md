# Price source and bounded fallback — checked 2026-11-10

Pyth's [official NEAR integration page](https://docs.pyth.network/price-feeds/core/use-real-time-data/pull-integration/near) says NEAR support ended on August 26, 2026. Its [current contract registry](https://docs.pyth.network/pro/contract-addresses) no longer supplies supported NEAR testnet or mainnet IDs. Consequently neither network has a currently maintained ID to verify there. The old `pyth-oracle.testnet` / `pyth-oracle.near` names are historical, not recommended live endpoints; the proposed init explicitly uses `account_id: null`. No testnet transaction was sent to investigate availability.

The NEAR/USD **Core/Hermes** feed ID is `c415de8d2eba7db216527dff4b60e8f3a5311c740dadb233e13e12547e226750` (note `2eba`, not `2efa`). Verified against the official [symbols endpoint](https://pyth.dourolabs.app/v1/symbols?query=NEAR&asset_type=crypto), `Crypto.NEAR/USD`, exponent -8, Pro/Lazer ID 27. The [feed-ID documentation](https://docs.pyth.network/pro/price-feed-ids) identifies `hermes_id` as the Core identifier; Pro numeric IDs are not interchangeable.

`refresh_oracle` is public. If an explicitly approved Pyth-compatible contract is configured, it calls only that immutable account's `get_price_no_older_than(price_id, age)` and its private callback parses the official NEAR wire shape: decimal-string price/confidence, numeric exponent and publish timestamp. It rechecks publication age/future time, positive price, exponent/overflow, confidence ≤ configured basis points, absolute price bounds and monotone oracle publication times. Null, failure, oversized, malformed, stale or high-uncertainty responses do not refresh the cache. Fresh oracle prices take precedence for opens, reductions, sales and margin health; caller reduction hints are ignored. Reads never attest venue fills/equity. No production oracle deployment is claimed by mock tests.

While oracle is absent or stale, `set_keeper_price(price, observed_at)` accepts only the designated keeper, a non-future observation at most `max_age_seconds` old, and an observation no older than the fallback cache. Its price must remain in immutable `[min_price,max_price]`, independent of the previous update; repeated pushes cannot ratchet the range. Owner `set_reference_price` is subject to the same absolute bounds and cannot override a fresh oracle. A bounded caller reduction hint can be used when both caches are stale: it does not refresh opening/sale permissions. All reductions use the configured IOC band (1% in the plan), with an authorization-size bound `max(reserved_short,max_short_size)` and venue reduce-only flag.

This is bounded price authority, **not an independently verified market oracle**. The keeper can lie anywhere inside the range; no confidence is fabricated for fallback observations. Price motion outside the immutable range fails closed. It may prevent recovery fills and requires a fresh controller for a new range. The cancellation-only policy-v2 plan fixes $0.95–$1.05 around its dummy $1 reference; it must not be funded. Wider sandbox/research bounds are labelled and must not be mistaken for deployment settings. Initial configuration and mutable limits/owner attestations remain trust boundaries.

Tests cover the callback through real sandbox receipts, absent/stale/high-confidence oracle results, private callback rejection, out-of-order publications, fallback freshness, non-ratcheting endpoints and oracle precedence over hostile reduction hints.
