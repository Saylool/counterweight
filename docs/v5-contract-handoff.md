# V5 contract handoff

V5 keeps the v4 Borsh state and all v4 independent-exit-slot and permanent public MPC-subsidy controls. A new `v5:exit_anchor` extension stores the last authenticated oracle price or the conservative opening sell limit, together with opening owner-attested equity and a reserved-exposure high-water mark. The initializer seeds the fallback anchor from the owner-approved initial reference price. Keeper/owner cache changes never move it. On un-oracled additions, the anchor can only decrease; a new owner-settled flat-to-open epoch records a new actual sell limit. Fresh authenticated oracle responses can move the anchor legitimately. Mainnet opens require configured margin controls and the existing fresh owner margin attestation/health checks.

Every reduction authority shares one pricing function. A fresh configured authenticated oracle takes precedence over every caller price and uses the existing 100bps IOC buy allowance. Without it, a fresh mark must lie both inside the owner 24h time-locked min/max corridor and within 25bps of the anchor. The final buy limit is rounded down and capped by (a) mark +100bps, (b) anchor +100bps, (c) anchor plus 1% of the smaller captured/current owner-attested equity divided by the maximum reserved short exposure of the opening epoch when margin exists. Partial settlement cannot reduce that denominator. Reduce-only execution cannot increase exposure, so repeated or partial exit authorizations cannot compound that incremental price debit beyond 1% of the opening-attested equity for the exposure (and a lower current margin snapshot can tighten the price cap). Fees/funding, prior market moves relative to a new authenticated price, incorrect owner margin attestations and actual venue liquidation are outside that arithmetic price-debit cap. If margin is absent (testnet compatibility only; new mainnet opens require it), the price-debit bound is 1% of anchored notional, not a margin guarantee.

The opening `price_band_bps` for the v5 run must be **10bps**. At an unchanged market this keeps the ordinary mark within 25bps of the sell-limit anchor and permits a buy limit about 89.9bps above the opening market. The fallback deliberately rejects honest large moves: beyond 25bps of the anchor it fails closed. Tight IOC limits can be unfilled. It does not authenticate a caller mark; it bounds its adverse execution authority.

`get_exit_pricing()` returns `anchor_price`, `mark_band_bps:25`, `fallback_slippage_bps:100`, `max_fallback_price`. For fallback tooling, compute/quantize downward `min(mark*10100/10000,max_fallback_price)`. Fresh oracle pricing remains `quantize_down(oracle_price*10100/10000)`. Price setter interfaces and all existing state fields remain stable.

Build: `bash contracts/policy/tools/build-v5.sh`; pinned Binaryen123.0.0 and the exact v4 optimization sequence, fresh `/private/tmp` scratch, locked release Cargo build with no default features. New v5 WASM/checksum only. Tests and final hash are appended after verification.

Runtime signing keeps the unchanged 128KiB future-state storage reserve: `(storage_usage + 131072) * storage_byte_cost`, plus the configured MPC fee. A 5.5NEAR creation deposit minus approximately 3.5NEAR storage leaves about 2NEAR native balance, of which about 1.31072NEAR is this growth reserve. It is not all spendable operating balance.
